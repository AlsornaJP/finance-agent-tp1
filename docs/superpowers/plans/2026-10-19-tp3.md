# TP3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mover o agente de finanças para `agent1/` e expô-lo via FastAPI, criar o planejador de metas em `agent2/` com sua própria API, e produzir CLAUDE.md por agente, contrato de integração, avaliação final de prompts, workflow n8n e materiais de entrega.

**Architecture:** Dois projetos Python independentes no mesmo repositório, cada um com `pyproject.toml`, `.venv`, `.env` e `CLAUDE.md` próprios. Cada API expõe `POST /run` (202 + `task_id`), `GET /status/{task_id}` e `GET /health`, com registro de tarefas em memória executando uma tarefa por vez via `BackgroundTasks`. Nenhum agente importa, lê ou chama o outro.

**Tech Stack:** Python 3.12, OpenAI Agents SDK, Pydantic 2, FastAPI, Uvicorn, pytest + `fastapi.testclient` (httpx), uv, n8n (Docker).

**Spec:** `docs/superpowers/specs/2026-10-19-tp3-design.md`

## Global Constraints

- O LLM nunca calcula: toda aritmética fica em código Python (agente 1: `agent/database.py`; agente 2: `planner/simulacao.py`).
- Todo número citado em resposta é rastreável à tool de origem (`valores_citados`).
- Saída final de agente via `output_type` Pydantic.
- Sem comentários no código; nomes de variáveis e funções claros, em português, no estilo existente.
- Toda execução gera log salvo em arquivo (`prompts/outputs/` de cada agente).
- Nenhum agente importa código do outro, lê o banco do outro ou chama o outro por HTTP.
- Sem `CLAUDE.md` na raiz do repositório.
- Lógica do agente 1 intacta; a única mudança fora de `agent1/api/` é a proteção em `_confirmar_proxima_chave`.
- Comandos de cada agente rodam de dentro da pasta dele (`cd agent1` / `cd agent2`).
- Portas: agente 1 `8001`, agente 2 `8002`, host `0.0.0.0`.
- Estados de tarefa: exatamente `pending`, `done`, `error`.
- Cabeçalho de documentos de entrega: `**Aluno:** João Pedro Jacob · **Disciplina:** 26E3_5`.
- Commits em português, terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

**Regra de tempo (do spec):** dentro de cada task só `pytest`. Execução real de LLM somente nas tasks marcadas **[LLM real]**, uma vez, em segundo plano e sem loop de espera; se prevista para passar de ~5 min, perguntar antes ou entregar o comando ao aluno. **Ao fim de cada bloco, parar e pedir revisão do aluno.**

## Review Focus

- `diagnosticar` de um mês sem dados: a tarefa deve terminar `error` com a mensagem de `levantar_mes` ("Não há transações para …"), sem derrubar o serviço — teste na Task 4.
- Agente 2 com `prazo` igual ou anterior a `mes_referencia`, ou categoria repetida em `gastos_por_categoria`: `POST /run` deve responder 422 antes de criar tarefa — testes nas Tasks 5 e 8.
- Agente 2 com `saldo` negativo: os cortes precisam cobrir o déficit além da meta (`valor_a_cobrir_com_cortes = necessaria - saldo`) — teste na Task 6.
- Proposta final do LLM com corte maior que o gasto da categoria ou categoria ausente da entrada: `montar_plano` deve levantar `ValueError` com mensagem clara, virando `error` na tarefa — teste na Task 7.
- Exceção qualquer dentro do trabalho de uma tarefa: status `error` com `"<TipoDoErro>: <mensagem>"`, e as tarefas seguintes ainda executam — teste na Task 3.
